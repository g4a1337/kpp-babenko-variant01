# Інформаційна система опрацювання заявок ІТ-підтримки

Курсова робота з дисципліни «Кросплатформене програмування». Варіант 1.
Виконав Бабенко Дмитро Володимирович, група 204-ТН. Керівник Заїка С. О. Навчальний рік 2026–2027.

## Можливості

Чотири основні сутності: користувач, категорія, обладнання та заявка. Для кожної реалізовано створення, перегляд, редагування та видалення. Усі дані зберігаються в MySQL і передаються між JavaFX-клієнтом та сервером через HTTP/JSON.

Життєвий цикл заявки: **НОВА → ПРИЗНАЧЕНА → В РОБОТІ → ЗАКРИТА** (`NEW → ASSIGNED → IN_PROGRESS → CLOSED`). Пропуск і зворотні переходи заборонені. Для призначення необхідно обрати та зберегти виконавця з ознакою фахівця ІТ-підтримки. Зміна статусу виконується окремою кнопкою, а не редагуванням поля форми.

Пріоритет `I = 0,40 × F1 + 0,35 × F2 + 0,25 × F3`: F1 — терміновість, F2 — вплив на роботу, F3 — критичність обладнання. Фактори задаються безпосередньо в нормованій шкалі 0–100. Орієнтири: 0 — відсутній вплив, 25 — низький, 50 — середній, 75 — високий, 100 — максимальний. Дозволено проміжні числові значення. Більший I означає вищий пріоритет; це навчальна оцінка, а не обіцянка строку обслуговування.

F3 сервер бере з вибраного обладнання, а I розраховує самостійно. Передані клієнтом значення підсумку не вважаються достовірними. У заявці зберігається знімок F3: редагування обладнання не змінює автоматично старі заявки, а під час наступного редагування заявки її оцінка оновлюється за поточними даними обладнання. Приклад: F1=100, F2=50, F3=75 → I=76,25.

Спочатку кожен фактор округлюється до двох десяткових знаків, потім обчислюється зважена сума і результат округлюється до двох знаків. Використовуються десяткові обчислення `BigDecimal` і правило `HALF_UP`: наприклад, фактор 1,005 стає 1,01, а для F1=0, F2=0, F3=0,58 сума 0,145 дає I=0,15.

Імпорт переліку обладнання виконується в `JavaFX Task` з індикатором прогресу, підсумком і повідомленнями про некоректні рядки. Мережеві операції інтерфейсу також виконуються поза JavaFX Application Thread.

## Структура

```text
ITSupportCoursework/
  server/                 Maven WAR: model, dao, service, web, тести
  client/                 Maven JavaFX: model, api, csv, інтерфейс, тести
    sample-data/          CSV для імпорту
  database.sql            Структура MySQL і демонстраційні записи
  scripts/                Налаштування, запуск, зупинка та перевірка
  Start.cmd               Запуск локальної демонстрації Windows
  Stop.cmd                Зупинка локальної демонстрації
  .tools/                 Локальні інструменти та Maven-кеш, виключені з Git
  .runtime/               БД, локальні паролі та журнали, виключені з Git
```

Архітектура: `JavaFX → ApiClient → HTTP/JSON → Servlet → Service → DAO → JDBC → MySQL`.
Клієнт не містить JDBC-драйвера й не підключається до БД. Серверні Service перевіряють правила, DAO використовують `PreparedStatement` і `try-with-resources`. Тести сервісів використовують підмінні репозиторії без зовнішньої БД.

## Швидкий запуск на цьому комп’ютері

Двічі клацніть **Start.cmd** у папці проєкту. Скрипт використовує переносимі інструменти з `.tools`, запускає MySQL на `127.0.0.1:3307`, складає обидві частини, запускає Tomcat на `127.0.0.1:8080` та відкриває JavaFX-клієнт. Перший запуск може тривати довше через завантаження Maven-залежностей.

Для завершення роботи закрийте клієнт і запустіть **Stop.cmd**. Дані зберігаються між запусками в `.runtime/mysql-data`.

На іншому Windows-комп’ютері спочатку запустіть у PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Setup.ps1
.\Start.cmd
```

Setup завантажує офіційні ZIP-дистрибутиви Temurin JDK 21, Maven, MySQL і Tomcat 9 без реєстрації служб та зміни системного PATH. Потрібен Інтернет і вільні порти 3307 та 8080. Якщо порти зайняті, змініть `mysqlPort` та `httpPort` у `.runtime/settings.json` перед запуском; для вже створеної конфігурації Tomcat також змініть порт у `.runtime/tomcat/conf/server.xml`.

Обліковий запис БД і випадковий локальний пароль створюються скриптом. Пароль зберігається лише в локальному `.runtime/settings.json`, не додається до Git. Застосунок є локальною навчальною демонстрацією, інтерфейс входу та розмежування прав користувачів не передбачені індивідуальним завданням. Сервер і БД прив’язані до loopback.

## Збирання і перевірка у переносимому середовищі

Перед ручною повторною збіркою закрийте клієнт і виконайте `Stop.cmd`, щоб звільнити JAR-файли. Звичайний `Start.cmd` сам завершує попередній клієнт і Tomcat цього проєкту перед повторною збіркою та розгортає актуальний WAR.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start.ps1 -NoClient -SkipBuild
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\IntegrationCheck.ps1
```

Build виконує `mvn clean verify` для `server` і `client`. IntegrationCheck звертається до реального HTTP-сервера та MySQL, створює власні тестові записи й прибирає їх після завершення.

## Звичайний запуск через IDE або термінал

Потрібні JDK 21, Maven, JavaFX 21 (залежності Maven), MySQL 8.4 та Tomcat 9.x. Tomcat 10/11 використовує інший простір імен Servlet і для цього проєкту не підходить.

1. Створіть БД, виконавши `database.sql` у MySQL-клієнті. Скрипт містить `CREATE DATABASE`, таблиці, ключі, обмеження і демонстраційні дані. Повторний запуск зберігає наявні таблиці; демонстраційні записи з існуючими ID не перезаписуються.
2. Створіть окремого користувача MySQL з правами `SELECT, INSERT, UPDATE, DELETE` на `it_support.*`.
3. У середовищі процесу Tomcat задайте `DB_URL`, `DB_USER` та `DB_PASSWORD`.
4. У `server` виконайте `mvn clean package` і скопіюйте `target/it-support-server.war` у `webapps` Tomcat 9. Запустіть Tomcat.
5. У середовищі клієнта задайте `API_BASE_URL`, наприклад `http://localhost:8080/it-support-server/api`.
6. У `client` виконайте `mvn clean test javafx:run`.

Серверні параметри можна передавати змінними середовища. Приклад JDBC URL: `jdbc:mysql://127.0.0.1:3307/it_support?useSSL=false&allowPublicKeyRetrieval=true&characterEncoding=UTF-8&serverTimezone=UTC`. Реальні паролі не записуйте в код, README чи Git.

## HTTP API

Базова адреса: `http://localhost:8080/it-support-server/api`.

| Метод і шлях | Призначення |
|---|---|
| `GET /users`, `/categories`, `/equipment`, `/tickets` | Списки сутностей |
| `GET /{collection}/{id}` | Один запис |
| `POST /{collection}` | Створення, тіло JSON |
| `PUT /{collection}/{id}` | Редагування, тіло JSON |
| `DELETE /{collection}/{id}` | Видалення |
| `POST /tickets/{id}/transition` | Перехід, наприклад `{"state":"ASSIGNED"}` |

Сервер повертає JSON, а для помилок — об’єкт з полем `message`. Некоректні дані відхиляються з 400, відсутні записи — 404, конфлікти унікальності та зовнішніх ключів — 409. Внутрішні подробиці винятків записуються в серверний журнал.

## CSV обладнання

Кодування UTF-8, роздільник `;`, перший рядок — назви стовпців:

```csv
inventoryNumber;name;location;criticality
PC-CSV-001;Робоча станція Dell;Аудиторія 205;50
NET-CSV-001;Маршрутизатор;Серверна;100
```

Інвентарний номер — непорожній унікальний рядок до 80 символів; назва і розташування — непорожні рядки до 200 символів; критичність — скінченне число 0–100. Десятковий роздільник — крапка. Для значень із `;` використовуйте подвійні лапки, внутрішні лапки подвоюйте. Імпорт не є єдиною транзакцією: успішні рядки зберігаються, помилкові відображаються в підсумку. Повторний імпорт тих самих інвентарних номерів дає конфлікти, а не дублікати.

## Демонстрація на захисті

1. Показати чотири вкладки та початкові записи.
2. Створити користувача, категорію та обладнання; змінити й видалити непов’язані записи.
3. Створити заявку з терміновістю 100, впливом 50 і обладнанням критичності 75; отримати пріоритет 76,25.
4. Обрати фахівця, зберегти заявку, послідовно пройти чотири стани.
5. Продемонструвати відхилення некоректних факторів і захист обладнання, на яке є заявка.
6. Імпортувати CSV, показати прогрес і повідомлення про помилковий рядок.
7. Показати результати JUnit і пояснити маршрут запиту через шари.
