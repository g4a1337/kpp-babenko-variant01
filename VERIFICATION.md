# Результати перевірки варіанта 1

Перевірено 15 листопада 2026 року на Windows 11 x64. Сервер і клієнт зібрано JDK Temurin 21.0.13 та Maven 3.9.16; HTTP-сервер — Apache Tomcat 9.0.124; БД — MySQL Community 8.4.13.

| Перевірка | Результат |
|---|---|
| `CourseworkServiceTest` | 41 тест, 0 помилок |
| `ServletJsonTest` | 7 тестів, 0 помилок |
| `EquipmentCsvTest` | 12 тестів, 0 помилок |
| `ApiClientTest` | 7 тестів, 0 помилок |
| Разом звичайні JUnit 5 тести | 67 тестів, 0 помилок, 0 пропусків |
| `ImportEquipmentTaskIT` з реальною MySQL | 2 тести, успішні: імпорт та скасування |
| `scripts/IntegrationCheck.ps1` через Tomcat/MySQL | 31 перевірка, успішні |
| Пакування сервера і клієнта | `BUILD SUCCESS` для обох |
| Перезапуск переносимого середовища | Успішний; дані збереглися |
| Екрани JavaFX | Чотири вкладки відкрито з даними сервера, знімки перевірено |

Окремий клас `ImportEquipmentTaskIT` запускає справжній JavaFX Toolkit та `Task`, передає рядки через HTTP до працюючого сервера і перевіряє збереження через API з MySQL. Перший тест підтверджує: додано 2 записи, пропущено 2 помилкові, прогрес 1,0; JavaFX обробляє подію під час виконання мережевої операції. Другий тест перевіряє запит скасування під час першого HTTP-запиту: поточний запис завершується, збережено рівно 1 із 3 записів, наступні запити не надсилаються, підсумок має `cancelled=true`, інтерфейс відповідає. Усі створені тестами записи видалено.

31 HTTP-перевірка охоплює початкові дані, CRUD усіх чотирьох сутностей, повторення email, межі факторів, серверний розрахунок I=76,25, заборону підміни стану через PUT, усі допустимі переходи, відхилення пропуску і зворотного переходу, захист пов’язаних користувачів/категорій/обладнання, відсутні ресурси та видалення. Створені перевіркою записи прибираються в `finally`.

Повторення звичайних тестів: `scripts/Build.ps1`. Результати Maven знаходяться в `server/target/surefire-reports` і `client/target/surefire-reports`.

Для окремої перевірки JavaFX Task спочатку запустіть сервер (`scripts/Start.ps1 -NoClient -SkipBuild`), потім у PowerShell:

```powershell
. .\scripts\Environment.ps1
& "$MavenHome\bin\mvn.cmd" "-Dmaven.repo.local=$ToolsRoot\m2" -f .\client\pom.xml -Dtest=ImportEquipmentTaskIT "-Dit.api=$env:API_BASE_URL" test
```

Тест потребує доступного графічного сеансу Windows та працюючого сервера. За замовчуванням Maven не запускає файли `*IT`, тому звичайна збірка і 67 тестів не залежать від запущеної MySQL або JavaFX-дисплея.

## Повторна перевірка перед поданням

Перевірено чисту копію опублікованих вихідних файлів в іншій папці з пробілом у назві. `mvn clean verify` завершився успішно для обох частин: 48 серверних і 19 клієнтських тестів без помилок та пропусків.

Для перевірки першого запуску створено окрему порожню MySQL на порту 3308 і Tomcat на 8081. Запуск виконано саме через Windows PowerShell 5.1, який використовує `Start.cmd`, з окремими випадковими локальними реквізитами. Схема, обліковий запис і демонстраційні записи створилися; українське ПІБ збережено правильно. На цій БД пройшли 31 HTTP-перевірка, два справжні JavaFX Task тести і запуск усіх чотирьох екранів клієнта. Тимчасове середовище зупинено, основна БД не змінювалася.

Під час повторної перевірки виправлено дві несумісності допоміжних сценаріїв із Windows PowerShell 5.1: очікувана помилка початкової перевірки пароля більше не припиняє налаштування MySQL; завантаження у `Setup.ps1` використовують `-UseBasicParsing` і не залежать від налаштування Internet Explorer. `Setup.ps1` повторно запущено з наявними переносимими інструментами; повторне скачування всіх дистрибутивів не виконувалося.

У пояснювальній записці відновлено повний офіційний бланк першого індивідуального завдання, наведено 14 конкретних автоматизованих перевірок з очікуваними результатами, уточнено обов’язковість CSV-полів і наведено узгоджений приклад імпорту з фактичним результатом. Після змін перевірено сторінки та зміст документа.
